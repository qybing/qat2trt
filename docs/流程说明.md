# QAT → INT8 流程说明（给小白）

## 1. 一句话理解

训练时已经做了「量化感知训练（QAT）」，量化范围写在 `.pt` 里。  
本项目只是把这些范围写进 ONNX，再编成 TensorRT 的 INT8 引擎。

**所以不需要再准备几百张校准图**（那是另一条叫 PTQ 的路，本项目不做）。

---

## 2. 流程图

```text
┌─────────────────────┐
│  QAT 训好的 .pt      │  ← 输入（训练时 quantize=8）
└──────────┬──────────┘
           │  脚本① export_yolo11_qat_onnx.py
           ▼
┌─────────────────────┐
│  Q/DQ ONNX           │  ← 中间文件（含 QuantizeLinear）
│  + *_labels.txt      │
└──────────┬──────────┘
           │  脚本② onnx_qdq_to_engine.py
           ▼
┌─────────────────────┐
│  INT8 .engine        │  ← 输出（DeepStream 加载）
└─────────────────────┘
```

一键脚本 `run_qat_to_engine.sh` = ① + ② 串起来。

---

## 3. 每个脚本：输入 / 输出 / 怎么用

### 3.1 `check_env.py` — 环境检查（建议先跑）

| | |
|--|--|
| **输入** | 无 |
| **输出** | 终端打印各依赖是否 OK |
| **命令** | `cd /tmp && python3 scripts/check_env.py` |

---

### 3.2 `export_yolo11_qat_onnx.py` — 第 1 步

把 QAT `.pt` 导出成 DeepStream-Yolo 格式的 ONNX（带 Q/DQ 节点）。

| | |
|--|--|
| **输入** | `-w` QAT 的 `.pt`；`-s` 边长；`--batch` 静态 batch |
| **输出** | `-o` 指定的 `.onnx`；同目录 `<stem>_labels.txt` |
| **成功标志** | 打印 `QuantizeLinear: N`（N>0）；输入名 `input`；输出名 `output` 形状约 `(1,8400,6)` |

```bash
cd /tmp
python3 /home/jovan/code/qat2trt/scripts/export_yolo11_qat_onnx.py \
  -w /path/to/qat_best.pt \
  -o /home/jovan/weigth/onnx/xxx_qat_dsyolo_b1.onnx \
  -s 640 --batch 1
```

依赖同目录的 `export_yolo11.py`（提供 DeepStream 输出头，一般不用单独跑）。

---

### 3.3 `onnx_qdq_to_engine.py` — 第 2 步

把带 QuantizeLinear 的 ONNX 编成 INT8 TensorRT engine。**不读校准图。**

| | |
|--|--|
| **输入** | `-i` 上一步的 `.onnx` |
| **输出** | `-o` 的 `.engine` |
| **成功标志** | 打印引擎路径与大小；`input`/`output` shape 正确 |

```bash
cd /tmp
python3 /home/jovan/code/qat2trt/scripts/onnx_qdq_to_engine.py \
  -i /home/jovan/weigth/onnx/xxx_qat_dsyolo_b1.onnx \
  -o /home/jovan/weigth/engine/xxx_qat_dsyolo_b1_int8.engine \
  --workspace 2
```

---

### 3.4 `run_qat_to_engine.sh` — 一键（推荐）

| | |
|--|--|
| **输入** | `-w` `.pt`；`-o` onnx 路径；可选 `-e` engine 路径 |
| **输出** | onnx + labels + engine |

见 `快速开始.md`。

---

### 3.5 `export_yolo11.py` — 依赖模块

给 QAT 导出提供 `DeepStreamOutput`（把检测结果收成 `[N,6]`，方便 DeepStream 解析）。  
普通 FP32 导出也可以用它，但**本项目文档只讲 QAT**。

---

## 4. 输入输出对照总表

| 阶段 | 输入 | 输出 | 要不要校准图 |
|------|------|------|--------------|
| 训练（不在本项目） | 数据 + 配方 `quantize=8` | QAT `.pt` | — |
| 本项目第 1 步 | QAT `.pt` | Q/DQ `.onnx` + labels | **否** |
| 本项目第 2 步 | Q/DQ `.onnx` | INT8 `.engine` | **否** |
| DeepStream 部署 | `.engine` + 配置 | 视频检测结果 | — |

---

## 5. DeepStream 侧最小配置提示

```ini
model-engine-file=/path/to/xxx_int8.engine
network-mode=1
batch-size=1
infer-dims=3;640;640
maintain-aspect-ratio=1
symmetric-padding=1
num-detected-classes=你的类别数
custom-lib-path=.../libnvdsinfer_custom_impl_Yolo.so
parse-bbox-func-name=NvDsInferParseYolo
```

注意：
- `batch-size`、`infer-dims` 必须和导出时的 `--batch`、`-s` 一致  
- `.engine` 只能在**同一块 GPU + 同一 TensorRT 大版本**上用；换板子要重新编  

---

## 6. 常见报错

| 现象 | 原因 | 怎么办 |
|------|------|--------|
| 没有 QAT 假量化器 | `.pt` 不是 QAT 训出来的 | 换真正的 QAT 权重；或走 PTQ（本项目不做） |
| 没有 QuantizeLinear | 量化节点没写进 ONNX | 检查 modelopt / ultralytics 版本 |
| `import ultralytics` 奇怪 | 在错误目录下跑 | **始终 `cd /tmp` 再跑** |
| 建 engine 很慢 / 显存紧 | 正常或占用过高 | 关掉其它占 GPU 程序；`--workspace` 可试 1～2 |
| DeepStream 加载失败 | engine 有 Ultralytics 头 / 格式不对 | 必须用本项目的 `onnx_qdq_to_engine.py`（已关 metadata） |

---

## 7. 和「普通权重 INT8」的区别（避免混）

| | 本项目 QAT | 另一条 PTQ |
|--|------------|------------|
| 权重 | 量化训练过的 `.pt` | 普通 FP32 `.pt` |
| 校准图 | **不要** | **要** 几百张 |
| 脚本 | 本目录 `scripts/` | 例如 `pt2trt/ptq_onnx_to_int8.py` |
